# Ag-GIS identity

Ag-GIS is the farmer-facing product name. The original field-shaped A, sage
boundary line and harvest-coloured survey point connect fieldwork and mapping.
The short brand line is **Farming in view**. The supporting product wording is
**Built on open source tools**, allowing the identity to span multiple tools. Use calm farming language; retain
native QGIS controls and avoid promising cloud services that do not exist.

## Assets and application

- `plugins/ag_tech_tooling/icon.svg`: editable 96-unit symbol, also the plugin metadata icon.
- `plugins/ag_tech_tooling/brand_lockup.svg`: outlined vector wordmark, independent of runtime fonts.
- `installer/Ag-GIS.ico`: seven PNG-backed sizes, 16–256 pixels, for Windows setup/launcher/shortcut.
- Field green `#173F35`, sage `#8DB59A`, harvest `#D9AB55`, slate `#52665D`, warm white `#F5F2E8`.
- Keep the symbol square, preserve its proportions and leave at least one survey-point diameter of clear space. Use the symbol alone below a 140-pixel lockup width. Do not recolour or combine QGIS's logo with this mark.

The plugin toolbar has a compact wordmark. Plugins → Ag-GIS → About Ag-GIS
shows the logo, local-work description, open source tools wording
and licence reference. All owned workflow dialogs carry the Ag-GIS window icon and task title.
The plugin brands the current main-window title while retaining its map name
and unsaved marker. Project title updates are followed; unloading disconnects the
handler and restores the latest native title. The plugin changes the main-window icon,
restoring its previous icon on unload if another owner has not subsequently
changed it. There is no application-wide stylesheet or shared QAction rename.

The installer builder embeds the ICO into Setup.exe and Ag-GIS.exe. Setup creates
a per-user Start-menu shortcut and copies the product launcher/icon/config into
`%LOCALAPPDATA%\Ag-GIS\<profile>`. The launcher uses QGIS's original
`bin\qgis-ltr.bat --profile <profile>` bootstrap. Default setup continues to use
the existing `default` profile; another profile must be requested explicitly.
This is not an isolated profile migration. Native QGIS shortcuts remain usable.

## Rebuild and review

1. Prerequisites: Windows, QGIS 3.44.14, system Segoe UI fonts and .NET Framework C# compiler.
2. Run `& 'C:\Program Files\QGIS 3.44.14\bin\python-qgis-ltr.bat' tools/build_brand_assets.py` from the repository. This regenerates the outlined wordmark, Windows icon and `dist/branding/Ag-GIS-brand.png`. The editable text and geometry recipe are in this script and icon.svg.
3. Run `scripts/check.ps1`. The branding and launcher checks are included; extracted-package checks include the real Qt branding lifecycle. `dist/branding/Ag-GIS-about.png` is generated by branding_test.py.
4. Review the previews before building a new Windows installer. Use a newly captured source snapshot; old snapshots without branding assets are rejected. Never infer full release validity from the branding checks alone.

## Attribution and limits

QGIS trademark guidance reviewed 15 October 2026:
https://qgis.org/community/organisation/guidelines/ . It requires accurate
attribution and avoidance of implied endorsement; modified QGIS marks and product
names containing QGIS have additional permission requirements. These are original
Ag-GIS assets. Product copy refers to open source tools; upstream attribution
remains in the native application credits, licences and technical documentation. No trademark clearance is claimed.
Native About, dialogs, installed resources and upstream licences remain intact.
The product launcher now displays its own Ag-GIS startup screen and passes
--nologo to suppress the native splash. No installed splash/resource is replaced.
Binary application metadata and global file associations still need a separate
distribution approach.
Windows taskbar identity is assigned per window through the Windows property store,
with an explicit packaged app_icon.ico and the installed product launcher as its
relaunch command. The per-profile Start-menu shortcut has the matching AppUserModel ID.
These properties restore on unload without replacing another owner's later changes.
Existing upstream pins are separate; global executable icons/file associations remain native.

No source visibility change, release deployment or asset purchase is part of this
work. Repository visibility and release publication are managed separately. Optional backup, mobile
access and team sync are future capabilities, not part of this branding update.
